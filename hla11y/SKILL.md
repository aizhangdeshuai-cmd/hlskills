# 无障碍规范（WCAG 2.2 AA）

---

## 设计阶段

- **色彩对比度** — 正文文本 >= 4.5:1，大文本/UI组件 >= 3:1
- **交互目标。** 优先给可点击区域至少 24×24 CSS px。按 WCAG 2.2 AA 2.5.8 判定时，更小的目标可以满足间距、等效控件、行内文本、用户代理控件或必需呈现等例外。对间距例外，以每个较小目标的边界框中心画直径 24 CSS px 的圆，检查是否与其他目标或另一个小目标的圆相交。团队采用更大尺寸时，单列团队标准。[W3C 2.5.8 判定说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
  - 两个 16×16 CSS px 按钮，中心相距 20 CSS px，两个圆重叠。没有其他适用例外时应报告失败。
  - 同样两个按钮中心相距 32 CSS px，周围没有其他目标。满足间距例外，记录实测尺寸、间距及所用例外。
- **文本替代** — 所有非文本内容（图片、图标、图表）提供文本替代
- **信息传达** — 不仅依赖颜色传达信息，配合图标/文字/形状

## 开发阶段

### 语义化 HTML
```html
<!-- 好 -->
<button onclick="submit">提交</button>

<!-- 差 -->
<div onclick="submit">提交</div>
```

### ARIA 标签
- 交互元素优先用可见文本或关联的 label 命名。通过 aria-describedby 关联字段帮助或错误说明，出错字段设置 aria-invalid
- 动态内容使用 `aria-live` 区域

### 键盘导航
- 完整 Tab/Shift+Tab/Enter/Escape 支持
- 焦点顺序合理（按视觉顺序）
- 焦点状态有明显视觉指示器（outline/ring）

### 焦点管理
- 模态框打开时，焦点移入模态框
- 模态框关闭时，焦点返回触发元素
- 弹出菜单不得困住焦点

## 测试阶段

| 测试项 | 工具/方法 |
|--------|---------|
| 屏幕阅读器 | VoiceOver (Mac) / NVDA (Windows) |
| 键盘导航 | Tab/Shift+Tab 遍历全页面 |
| 模态框/菜单 | 模态框内循环 Tab，关闭后焦点返回触发处。菜单支持 Escape 关闭后继续键盘导航 |
| 错误恢复 | 触发多字段错误，用键盘从错误摘要跳到字段，确认读屏能播报对应错误；修正后验证状态清除 |
| 缩放和长文本 | 文本放大 200%，使用长名称或编号，验证标签、错误与主要操作仍可见、可操作 |
| 减少动态效果 | 开启系统减少动态效果，确认非必要动画停止，加载和完成状态仍可感知 |
| 对比度 | 浏览器开发者工具 Axe 插件 |

## 常见反模式（Code Review 必标）

| 反模式 | 正确做法 |
|--------|---------|
| `<div>` 作为按钮 | 使用 `<button>` |
| 仅用颜色表示含义 | 配合文字/图标 |
| `onclick` 无键盘处理 | 使用语义元素或添加 `onKeyDown` |
| 无焦点样式 | 添加可见的 `:focus-visible` 样式 |
| 图片无 alt | 添加有意义的 alt 属性 |
