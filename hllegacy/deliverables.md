# 旧项目九类交付物的编写与验收

完整接手时核对九项。专项分析只打开所选项和共同要求。沿用项目现有 `knowledge/` 中的主题正文，交接时提供文件和章节，索引与其他条目引用同一处。

归档时在现有条目的 Markdown 标题末尾加本项标记，每项使用一个标题。下列表头是对应的主清单，详细推导、图或证据可以紧随其后。状态、公共字段、证据写法和命令见[自动核对协议](verification.md)。

## 共同要求

- **统计口径。** 先结论后证据，清单标题或引导句注明实测总数。在文首说明实际仓库、模块、环境、采集日期和版本。有 Git 时记录分支或分离状态、提交号、影响结论的工作区变更。无 Git 时给出可复核的源码快照标识。多仓分别注明版本和已读取范围。数量有计数单位、来源和可重跑的命令或查阅步骤。
- **证据。** 每项结论指向文件、行号与符号，或能复核的脱敏实测记录。清单从第二种来源反查，同数仍需逐项比对身份。对重复、别名、生成物和排除项给理由。回读三个不同实例，少于三个时全查。优先选动态入口、异常分支或跨模块关系。记录实际抽查结果。
- **交付结尾。** 写清覆盖范围、独立核对结果、测试和工具是否实际运行、剩余偏差以及补查办法。数据库、接口、前端三项仅在证据支持能力确实不存在时标为不适用。技术债经排查确为零项时可记无发现。缺仓、缺权限、缺截图、工具失败、应查指标未经实测时标未完成，记录补查途径。结尾给可执行的禁止项或检查清单。证据位于外部时交接可重放的证据绑定和命令，在移交位置复验。
- **敏感内容。** 源码、命令输出、日志、截图及图表只引用脱敏证据。不得写入密钥值、认证头、生产连接串、真实个人数据或内部生产地址。涉及秘密时只保留配置项名、脱敏位置和处理状态。先检查原件可分享，再引用。
- **判定。** 自动检查核对可机械判定的项目。验收人仍需打开证据，判断它能否支持结论，登记剩余不确定性。拟作为开发红线的新约束或例外，由有权的项目负责人确认后再按生效规则交接。基线报告可以记录失败的测试或仍开放的风险。谎报通过、缺报风险或遗漏应核范围会阻止报告完成。

## 1. 项目技术栈清单

标题标记 `<!-- hllegacy:stack -->`。

| 标识 | 类别 | 版本依据 | 用途 | 证据 |
|---|---|---|---|---|

- **输出格式**　按仓库与服务列出语言及占比、组件、类别、用途、声明版本、实际解析或运行版本、版本来源。另列各端的构建、启动、测试与部署入口，给出前置环境、命令、可观察结果及外部集成边界。
- **硬性要求**　生产、开发和构建依赖分开。记录 manifest、锁文件、镜像或运行时版本各自证明什么，锁定版本与声明范围分列。项目使用多种语言或多个工作区时逐一覆盖。
- **禁止内容**　禁止从 import、目录名推断精确版本，禁止把本机安装版本充当生产版本，禁止将声明的版本区间改写成精确值。
- **验证方法**　从工作区、构建与部署入口反查实际会使用的清单，再核对解析版本。不同服务同时使用同一组件多个版本时保留差别。
- **不能算完成**　漏掉已参与构建的子工作区、把版本冲突合并成一个数，或声称已确认运行版本却缺运行证据。仓库只声明范围时可以如实交付该范围，同时注明运行版本的可验证边界。

## 2. 模块架构说明

标题标记 `<!-- hllegacy:modules -->`。

| 标识 | 职责 | 边界与依赖 | 入口 | 证据 |
|---|---|---|---|---|

- **输出格式**　列模块、职责、入口、文件与规模、上游、下游、持有的数据和证据。标注关键业务路径与有依据的耦合判断。首页速查指到同一份修改清单、适用分层规范及贯穿各层的可运行示例。
- **硬性要求**　边界以实际构建目标、注册入口、接口或数据所有权为依据。对关键业务动作追到写入方或消费端，区分明确约束、工具强制与观察到的惯例。[改动清单与分层规范](change-review.md)
- **禁止内容**　禁止把一层目录直接断定为一个服务，把共享库列成运行实例，把调用次数当作依赖方向。
- **验证方法**　从模块注册或构建清单核对模块集合，再沿关键入口正向追调用、从消费端反向找调用方。抽查跨层的正例与历史例外。
- **不能算完成**　漏掉独立注册的模块、边界与实际写入方不符、关键依赖没有可定位来源，或分层规则与代码冲突却没有记录双方证据。

## 3. 逻辑架构图

标题标记 `<!-- hllegacy:architecture -->`。

| 标识 | 起点 | 终点 | 数据或动作 | 证据 |
|---|---|---|---|---|

- **输出格式**　用 Mermaid 的 `flowchart`、`graph` 或 `sequenceDiagram` 画出有方向的调用或数据流图，附可逐行核对的连线清单。连线说明起点、终点、传递的数据或动作、同步/异步方式、证据。外部系统与本仓模块应能一眼区分。
- **硬性要求**　图中使用稳定节点名，节点可对应模块清单或有据可查的外部边界。核心流程体现入口、处理、数据读写和出口，注册表、消息订阅、回调按实际方向表示。
- **禁止内容**　禁止将包依赖当成实测网络请求，禁止把未看到的外部实现补成内部节点，禁止用无图例的双向箭头掩盖未知调用方向。
- **验证方法**　逐一对照图中节点、连线清单与源码。至少沿一个核心动作走通，交代用户最终收到的结果。若有正常与异常两条出口，分别给出触发条件及响应。异步链路核对发送事件与消费注册。实际单进程也可画函数/组件边界。
- **不能算完成**　图与连线清单不一致、节点悬空、跨模块边无证据、核心流程在已知回调前中断，或把推测的瓶颈写成实测结果。

## 4. ER 图与数据库设计

标题标记 `<!-- hllegacy:database -->`。

| 标识 | 实体与键 | 关系或约束 | 迁移或索引 | 证据 |
|---|---|---|---|---|

- **输出格式**　给 Mermaid `erDiagram`、实体/表清单、关键字段及类型、主键/外键、索引与唯一约束、迁移基线。关系项标明物理约束或业务关联，按实际标注基数、分区和数据量口径。单实体可画实体属性，无须虚构关系。
- **硬性要求**　注明方言、环境与迁移版本，从迁移、建库脚本或实际生效的模式定义验证实体、键、约束及关系两端。已获得的脱敏结构导出可作为独立来源。容量数据注明来源与日期，没有观测数据时写明未测。
- **禁止内容**　禁止凭同名字段虚构外键、从单条迁移猜当前模式、把测试数据规模当生产规模，或抄录业务记录与连接串。
- **验证方法**　用迁移链最终状态独立比对模型或结构导出，逐项核对表身份、FK 方向、引用列、约束是否为唯一及能否为空，再与图的两端基数比较。使用物理模式推断时区分复合唯一、部分索引与全表唯一。动态用户库区分应用自有结构与样库。页面显示和物理对象分母不同时给出口径和实测。ER 关系的机器证据绑定见[核验协议](verification.md)。无关系数据库时检查依赖、持久化配置和读写实现，再说明实际存储方式。
- **不能算完成**　漏表或键、关系与图不符、迁移和模型分歧未解释。使用了数据库而定义在不可读外仓时，须标出未核范围，不能把该项判成不适用。

## 5. API 端点清单

标题标记 `<!-- hllegacy:api -->`。

| 标识 | 调用方 | 输入 | 输出 | 权限 | 证据 |
|---|---|---|---|---|---|

- **输出格式**　每个对外端点一行，给方法与完整路由、处理器、认证/授权、入参、成功与失败响应、调用方、来源。限流、版本和可用条件按实际配置补充。
- **硬性要求**　HTTP 标识用“方法 完整路径”，包含挂载前缀与适用版本。业务方法逐行列。框架自动生成且行为一致的 HEAD/OPTIONS 可移到工具读取的清单，列明框架来源并保留有独立行为的例外，完整方法身份仍逐项对账。项目对外提供 RPC、事件或 CLI 契约时以协议类型加实际服务方法、事件或命令标识。将生成、嵌套、条件或配置注册纳入检查。入参记录对外原名、所在位置及是否可重复。表单的多值属性单列，只有真实字段名含方括号才把括号写进名称。与调用方、服务端取值和文内示例逐字核对。
- **禁止内容**　禁止以控制器文件数代替端点数，把 DTO 当作路由注册证明，或把缺少局部鉴权注解写成匿名可访问。
- **验证方法**　从真实注册清单、框架路由导出或部署入口枚举身份，与处理器清单逐项核对，解释别名和排除项。对任务涉及的契约，在隔离样例重放最小请求，保存真实字段、响应类型、附件名或数据变化。断言成功与异常各自的可观察结果。两个操作即使状态码相同也可能产生不同结果，相邻入口须分别证实条件。再抽查全局鉴权。运行观察与人工剩余项按[核验协议](verification.md)记录。没有 HTTP 能力时核对其真实入口。
- **不能算完成**　对外字段名、重复规则、响应类型、数据影响、适用条件与实测不符，方法或前缀错误，已注册端点未进入清单、声称端点公开却未核对全局中间件，或以静态扫描覆盖了全部动态路由作结而没有注册依据。

## 6. 前端设计规范文档

标题标记 `<!-- hllegacy:ui -->`。

| 标识 | 状态 | 样式值 | 交互 | 截图 | 证据 |
|---|---|---|---|---|---|

- **输出格式**　按页面/组件与交互状态列视觉值、单位、来源 token/选择器、视口/主题和对应本地脱敏截图。覆盖实际使用的字体族与字号/行高、主辅与语义色、按钮/表格/表单/筛选/弹窗等控件、图标、间距、边框、导航与响应式断点。记录焦点、选择、加载、空、错误、确认和通知中实际存在的状态，给出复现步骤、组件复用方案和样式覆盖来源。
- **硬性要求**　源码与渲染共同取证。引用真实组件或样式变量，截图绑定版本、页面、视口和状态。测量值与设计 token 不同须解释缩放、继承、覆盖或断点。复用现有知识条目与截图位置。
- **禁止内容**　禁止把示意图、生成图或竞品截图当作实测，禁止凭目测填像素值，把静态截图当成交互成功的证据，或在截图中暴露用户信息。
- **验证方法**　在实际页面触发代表性流程，检查默认态、受影响的边界态与相应反馈，核对计算样式和截图。绑定真实页面或路由、动作、视口、状态、关键控件、截图及运行结果。优先捕获完成任务所用的控件，核对状态变化、下载或数据效果。机器检查的观察记录与截图绑定方式见[核验协议](verification.md)。检查项目实际支持的视口/主题。无前端时核对入口、构建和依赖。
- **不能算完成**　有页面却未渲染、截图与版本或状态无从关联、关键组件只有视觉猜测，或已发现差异却声称可等比例复现。

## 7. 代码质量基线报告

标题标记 `<!-- hllegacy:quality -->`。

| 标识 | 口径 | 实测结果 | 方法 | 证据 |
|---|---|---|---|---|

- **输出格式**　按指标列对象及范围、工具/版本、命令、样本或分母、实际值与单位、已知限制。在任务速查给出可复制的回归命令、样例位置、环境和预期判据。分别记录测试执行统计、可获得的覆盖率、重复率、圈复杂度分布及前 20 个热点文件（不足时全列）、hlcode 可测的代码异味密度，定位高风险项。
- **硬性要求**　注明排除生成物与供应商代码的口径。把收集的测试数、执行数、通过/失败/跳过以及行/分支覆盖率分开。随工具写明每个指标的定义。
- **禁止内容**　禁止把未运行写为零、把通过率当覆盖率、用无范围的平均值掩盖单模块缺口，或把不同版本、不同分母的两个结果宣称为趋势。
- **验证方法**　核对测试报告、覆盖报告或静态分析输出，复核与汇总对应的总数和分母。从高值文件回读具体代码。工具不可用或基线测试失败时记录命令、现象及影响。
- **不能算完成**　声称已测的指标没有证据，汇总与原报告不符，或关键路径没有可复核质量数据却给出全项目通过结论。

## 8. 安全基线报告

标题标记 `<!-- hllegacy:security -->`。

| 标识 | 检查范围 | 方法 | 发现与影响 | 处置 | 证据 |
|---|---|---|---|---|---|

- **输出格式**　按依赖、凭据、认证授权、数据与外部信任边界等适用检查面核对 OWASP Top 10，列覆盖范围、方法、结果及限制。发现项列标识、受影响位置、风险等级及理由、脱敏证据、处置与复验方法。
- **硬性要求**　分开列源码、本地解析依赖、发布构件与部署环境各自的结果。注明依赖锁定版本、扫描时间及公告/规则库口径，区分可复核发现与待确认项。扫描、配置检查和代码审阅分别记证据。本地静态审查的结论限定在已读范围。
- **禁止内容**　禁止复制可用凭据、真实身份数据或线上地址，禁止把未运行扫描、过期离线结果、无告警或覆盖单一工具写成“项目安全”。
- **验证方法**　对照依赖锁和实际生效的鉴权/授权边界，以脱敏位置回查发现项。无发现时同样保留覆盖清单与实际结果。复核日志、摘录与图片均已脱敏。
- **不能算完成**　关键检查面既无结果也无范围说明、漏洞归属和版本不符、未核实的告警被写成确认发现，或报告含敏感原值。已复核的开放风险必须随报告交接。

## 9. 技术债清单

标题标记 `<!-- hllegacy:debt -->`。

| 标识 | 严重性 | 影响 | 改进与验收 | 证据 |
|---|---|---|---|---|

- **输出格式**　每项给稳定标识、症状与源码位置、具体影响、严重性及理由、建议措施、退出条件或回归检查、处置状态。经确认的责任方和关联问题可直接引用原记录。
- **硬性要求**　以质量、安全、架构基线或已有 issue 反查来源，说明为何是当前版本的工程债务。使用“严重、重要、次要”分级并给理由。重复出现的同一根因归并，影响范围可追溯。等级相同也需说明哪些会阻塞本次改动或验收。零项也要交代排查了哪些来源。
- **禁止内容**　禁止把个人风格偏好当作缺陷、把同一问题跨报告重复计数、虚构优先级依据或责任人，或把“已提单”登记为“已解决”。
- **验证方法**　逐项对照源码或基线证据、确认是否已有同一问题、按影响核对分级。已关闭项回读修复与实际复验结果。开放项定义读者能执行的完成判据。
- **不能算完成**　问题无法定位、严重性无依据、措施没有验证条件、与基线相矛盾未解释，或因尚未整理发现项直接写“无技术债”。
