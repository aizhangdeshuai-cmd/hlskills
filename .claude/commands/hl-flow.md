# hl-flow ── hlskills 单人全流程

加载 `hl-flow` 子技能(SKILL.md 在 `hlskills/hl-flow/SKILL.md`),按其 4 阶段流程单人跑完整路径。

## 流程结构(源 SKILL.md L46-107,完整版)

### 第零阶段:加载上下文(1 步)

- **0** 加载已有文档(读 docs/ + knowledge/ + .hl/memory/,避免孤立分析)

### 第一阶段:需求与设计(7 步)

- **1** 需求分析(`analyst`)
- **2** 竞品分析(`analyst`,新项目必须;可调 `market-research` 外部技能)
- **3** PRD 编写(`analyst`)→ 写入文件
- **4** PRD 评审(联合会议,`analyst` 主持,全体参与)
- **5** UI/UX 设计(`designer`)
- **6** 设计评审(联合会议,`designer` 主持)
- **7** ★ **用户确认设计**(硬性关卡,未确认**禁止**后续阶段;从 hlpm 进入且设计未变更可跳过)

### 第二阶段:测试准备(2 步)

- **8** 测试用例编写(`test-engineer`,含 E2E 场景)
- **9** 用例评审(`test-engineer` + `analyst`)

### 第三阶段:开发(7 步)

- **10** Git 工作区准备(隔离工作区,避免污染主分支)
- **11** 开发计划(`planner`,任务粒度 = 单步 2-5 分钟可完成,无占位符/TBD)
- **12** 架构决策记录(`architect`,→ docs/adr/NNNN-slug.md)
- **13** 开发(`executor`,前端+后端,TDD 覆盖率 ≥80%)
- **14** 代码审查(`code-reviewer`,按严重/重要/次要分级)
- **15** 前后端联调
- **16** 前后端自测(`executor`)

### 第四阶段:测试/审查/发布(7 步)

- **17** 安全审查(`security-reviewer`)
- **18** 测试用例执行(`qa-tester`)
- **19** 浏览器验证(`qa-tester`)
- **20** 生产审计(`verifier`)
- **21** 交付(更新文档)
- **22** ★ **用户确认发布**(硬性关卡)
- **23** ★ **用户确认部署**(硬性关卡)

**总 23 步,3 个硬性关卡**(7/22/23)。

## 与其他子技能对比

- `hl-flow` = 单人/小团队(一次性跑完,**含发布部署**)
- `hlpm` + `hldev` = 多角色协作(产品段产文档 → 开发段接文档,不含发布部署)
- `hlchain` = 跨阶段编排(Agent 按文档顺序自动加载 hlpm → hldev → hlrelease → hldeploy)

## 关键铁律

- **3 个硬性关卡**:用户确认设计(7)、用户确认发布(22)、用户确认部署(23)
- 推荐 **TDD** + 覆盖率 ≥ 80%
- 任务粒度 = 单步 2-5 分钟,**无占位符 / 无 TBD**
- 单人全跑,**不分工**

## 调用方式

- **有实参**(如 `/hl-flow 为登录加短信验证码`): 实参作为需求输入,从第 0 步开始
- **无实参**: 走第 0 步加载上下文 → 第 1 步询问需求
- **典型耗时**: 半天-2 天(单人连续执行)
