# hlpm ── hlskills 产品段

加载 `hlpm` 子技能(SKILL.md 在 `hlskills/hlpm/SKILL.md`),按其 4 阶段 13 编号步流程处理用户需求。

## 流程结构(源 SKILL.md L65-100,完整版)

### 第零阶段:加载上下文(3 步)

- **0** **加载已有文档** — 读项目 docs/ + knowledge/ + .hl/memory/,避免孤立分析
- **0.5** **★ 规模判断 + 设计需求 + 评审模式**(`analyst` 启动后**阻塞点**,一次性 `AskUserQuestion` 问 3 问题):
  - 规模:轻量(规则<3 条/1 模块/<100 行)/ 标准(3-10 条/2-3 模块)/ 复杂(>10 条/多角色/NFR)
  - 设计:涉及 / 不涉及(纯后端/接口/状态机/规则可跳 6/7 设计阶段)
  - 评审:分阶段(逐文档立即评)/ 集中(交付后 9c 一次性评)
- **0.6** **版本目录选择**(自动派生为主,如 v1/ v2/;不单独阻塞)

### 第一阶段:需求(5 步)

- **1** **需求分析**(`analyst`)— 理解 + 梳理新需求,含术语沉淀到 knowledge/glossary.md
- **3** **目标用户画像 / 差异化定位**(仅新项目)
- **4** **PRD 编写**(`analyst`)
- **5** **★ PRD 评审会签**(重量评审 1/3,阻塞点,**仅"分阶段评审"模式**)

### 第二阶段:设计(v11 条件性:仅当 0.5 选"涉及设计")

- **6** **设计规范检查** + 保真度规范(**v21 起默认档二,不再阻塞询问**)
- **6a.2** **设计保真度规范**(v21 默认档二,非阻塞,**钉点必须用 bl-marker**)
  - **🚨 v21 重大变更**:取消 v18 的"档一/档二"二选一,**默认统一为档二** = 高保真生产态 + 钉点逻辑说明活文档(2 文件)
  - **2 文件结构**:
    - `docs/{ver}/design/<page>.html` — 生产态(高保真,所见即开发交付,**无** DEV-NOT-FOR-PROD)
    - `docs/{ver}/design/<page>.demo.html` — 活文档(钉点 + 抽屉 + 悬浮开关 + 调试面板)
  - **🚨 钉点系统硬性约束**(v21 新增):
    - 活文档 demo.html **必须用 hlskills bl-marker 钉点系统**(参照 `hlpm/templates/bl-marker/bl-marker-template.html`)
    - **禁止**:inline `<span title="BL-1">i</span>` 简陋 tooltip / 自己造悬浮框
    - **必须**:引 bl-marker.css + bl-marker.js + 用 `<button class="bl-pin" data-bl="blN">N</button>` + 填 REQUIREMENTS 对象
  - **两文件共同要求**:纯静态 HTML 双击即开 / 真实交互可点 / 真实示例数据 / URL 参数切态(`?state=error`)/ bl-marker 调试模式 `?bl-test=1`
- **6b** **设计稿产出**(`designer`,按默认档二产出 2 文件)
- **7** **★ 设计评审会签**(重量评审 2/3,阻塞点,**仅"分阶段评审"模式**)

### 第三阶段:测试准备(2 步)

- **8** **验收用例编写**(`test-engineer`,含 E2E 业务路径骨架) + 沉淀 knowledge/tests/
- **9** **★ 用例评审会签**(重量评审 3/3,阻塞点,**仅"分阶段评审"模式**)

### 第三阶段.5:集中评审(可选)

- **9c** **集中评审**(5 角色一次评,仅"集中评审"模式时执行)

### 第四阶段:交付前终检(3 步)

- **10** **非功能需求打包**(性能/安全/兼容 3 子表,→ knowledge/{dependencies,env-vars}/)
- **11** **交付物自检**(`analyst` 用 `handoff-package.md` 逐项核对 → 输出自检报告)
- **12** **打包交付**(8 项产物 → docs/v{N}/)

## 关键铁律

- **产品段绝不修改代码**,仅产出文档(PRD/用例/验收/非功能)
- 与 `hldev` 配套使用:产品交付物评审通过后交接开发
- **3 个阻塞点**(★):步骤 0.5 规模 + 步骤 5/7/9 评审会签,没用户确认不前进
- **集中评审 vs 分阶段**:默认分阶段(逐文档立即评),集中评审作为可选 C 模式

## 8 项交付产物(→ hldev 步骤 0 验证)

- **5 必出**:PRD / 验收用例 / 非功能 / 一致性矩阵(含验收标准) / 自检报告
- **3 条件出**:竞品分析 / 设计规范 / 设计稿截图

## 调用方式

- **有实参**(如 `/hlpm 为登录加短信验证码`): 实参作为需求输入,从第 0 步开始
- **无实参**: 走第 0 步加载上下文 → 第 0.5 步阻塞询问规模/设计/评审
- **典型耗时**: 30 分钟-2 小时(看评审轮数)

详见 `hlskills/hlpm/SKILL.md` + `disciplines/` 子目录完整纪律。
