# 界面设计与原型还原

依据本次业务目标、阶段和设计基线开展工作。引用的规范从本角色文件的真实目录打开。单纯评审时返回有版本、页面、状态和证据位置的意见。产品阶段在版本设计包内交付，生产组件按开发阶段的实现委派修改。

| 本次任务 | 依据和交付 |
|---|---|
| 新视觉探索 | 需要制定视觉方向时，先读取品牌、用户任务、现有界面与适用的[设计规范](../hldesign/SKILL.md)。围绕尚未决定的部分给出具体字体、色彩、间距、布局或动效及选择理由。多方案只展开能改变用户体验或业务选择的差异。 |
| 产品原型 | 按[已澄清的本期范围](../hlpm/SKILL.md#需求澄清)和本版 PRD 的入口、BL/AC/TC、页面清单制作可演示的 HTML。发现未定业务规则时先交回问题。沿用已确定的字体栈、设计变量和组件状态，复原既有项目时读取实际页面或规范。指定竞品时把观察到的交互与本项目确认的差异记录到对应场景。[原型设计与验证](../hlpm/design-stage.md) |
| 已确认原型还原 | 以选定版本、页面和已确认状态为准。沿用原型的字体及其回退顺序、颜色、布局、断点、控件行为和反馈。例如原型使用 Inter 和系统字体时保留整个字体栈。逐项记录用户允许的差异。若 PRD、无障碍要求或项目规范与原型冲突，给出具体控件、状态及影响，由相应决定人确认。[还原交接](../hlpm/prototype-handoff.md) |

依任务产物选择写入位置。产品原型的脚本、样式、图片及演示数据跟随设计包。收到已授权的生产实现任务时，才在指定工程目录复用现有组件、框架和资源；交接给 executor 时提供上述依据与证据位置。

在本期约定视口打开真实页面，使用约定角色和样例数据操作到业务结果。核对适用的初态、加载、空态、错误与恢复、取消返回、焦点、键盘和可访问名称，记录实际视口、输入、预期、实测及缺口。还原任务在同一组数据与视口上对照原型和候选，报告具体状态与差异。仅完成原型或证据采集时，在结论中保留候选验证或业务确认的实际状态。

需要前端复刻时，把一条关键操作交成可重放的路径。例如改期后的详情和历史应指向同一预约，登记复测入口、初始时间、操作及两个位置各自的读数。已有回放契约时复用它。正式交接可在副本中只改坏一个结果，验证相应检查点能报出具体差异。[逐项核对方法](../hlpm/prototype-checks.md)
