# 保持行为的代码简化

在用户指定或本次变更范围内独立简化代码。用工作区差异定位待评估改动，读清调用者、导出接口、输入输出、错误处理和副作用。按周边代码的语言和项目约定选择写法，保留解释业务约束的注释。选择能具体减少重复、分支或阅读负担的位置。

1. **固定改前基线。** 在现有改动之上、开始简化之前，从真实入口运行直接覆盖待改逻辑的检查。记录输入、环境、命令、执行的断言或可复查的实际结果。涉及多个消费者时核对各自可见的输出；涉及写入时比较写入对象与次数，包含受影响的边界、拒绝或异常路径。
2. **确认覆盖。** 核对报告中实际执行了相应行为。退出码为 0 但收集到零条用例、相关用例全部跳过，或只通过编译时，仍缺行为基线。可在临时副本用代表性输入直接调入口或运行已有回放。若仍无法观察关键结果，跳过该处并将所需断言交给 test-engineer。新增持久测试或修改文档按委派范围办理；使用 hlrefactor 时沿用其[重构基线](../hlrefactor/SKILL.md)。
3. **应用并比较。** 每次处理一个可独立验证的简化。优先使控制流和命名清楚，保持接口、默认值、求值顺序及副作用。用同一命令、相同输入、等价初始状态重跑，同改前逐项比较。执行项目适用的类型检查或构建以及受影响模块的回归，核对实际覆盖和退出码。
4. **交付。** 报告修改位置、可读性收益、前后可观察结果、验证命令与缺口。发现行为变化或构建失败时只修正本次简化；一次明确修正后仍无法恢复基线，则撤回本次改动，保留用户原有改动并说明原因。无实质收益的候选直接跳过。
