# 验收用例设计

以用户确认的需求、接口契约和既有行为为依据。先列角色、业务对象和可观察的结果，据此选择下表中适用的边界。例如只有业务提供撤回入口时才验证撤回。规则未定时写明谁需决定、会影响哪条用例。涉及行业限制时使用用户确认的状态与依据。

| 检查维度 | 可观察的行为 |
|---|---|
| 防重复提交 | 在首次请求完成前连续操作，按契约核对单号、写入次数、反馈和按钮恢复。 |
| 切换 Tab 与多入口 | 切换、返回、刷新后，从同一对象核对数据、筛选与分页的保留或重置。 |
| 逆向状态 | 支持撤回、恢复或冲正时核对合法流转、关联记录和副作用。不可逆时核对拒绝和原状态。 |
| 软删除 | 逐一核对契约涉及的查询、统计、导出和恢复入口是否还能看到记录。 |
| 输入边界 | 按实际字段测试空值、边界内外、合法长度和超长后的提示、焦点与保存结果。 |
| 特殊字符 | 用包含中文、引号、尖括号的普通业务文本验证存取往返和页面文本展示，检查项目既有转义及参数化约定。 |
| 筛选 | 区分已生效和编辑中的条件。检查空筛选、单项、边界、组合条件以及零条结果。 |
| 分页 | 准备跨页数据，验证首页、末页、页长切换、删去末页末条后的结果及总数。 |
| 字段显示 | 检查零、空、负数、日期、长名称与截断后的完整读取方式。 |
| 多条明细 | 按约定规模验证行号、保存的明细数、翻页和性能目标。缺性能目标时记录样本规模和耗时。 |

对收费、余额、审批或权限场景，写清前置账户与归属、合法及拒绝路径、前后状态、失败恢复和实际副作用。有跨端接力时写清下一角色如何找到并核对同一对象。把预期写成能揭示错误的具体断言，并用稳定 TC 关联 AC、适用维度和原始依据。备注未覆盖项目及原因。[产品用例和验收计划](../hlpm/handoff-package.md#验收计划)
