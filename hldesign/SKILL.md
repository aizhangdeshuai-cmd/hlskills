## 设计依据优先级

用户指定竞品时，先明确要沿用的外观或操作及项目约束，按[竞品 UI 取证与还原](../hlpm/competitor-ui.md)将观察落实到控件与场景。已给出的参考和偏好直接使用。项目品牌、可访问性要求和参考有差别时，记录商定的做法及对应验收条件。

### 1. 有设计规范文档
严格遵循项目已有的设计规范文档(设计系统、组件库、色彩/字体/间距规范),`designer` 不得偏离既定规范。

### 2. 无设计规范文档
`designer` 从需求与已给参考整理以下信息，影响本次设计且尚未明确的选择再向用户询问。

- **设计风格偏好** — 极简、科技感、可爱、企业级、Material Design 等
- **色彩倾向** — 主色调、是否有品牌色
- **参考案例** — 用户是否有喜欢的同类产品界面(可读取截图/设计稿,用 Read 工具分析视觉特征)
- **响应式需求** — PC端 / 移动端 / 平板适配范围
- **参考图片** — 如用户提供参考设计图/截图,使用 Read 工具读取,提取色彩/字体/布局/间距

## 代码级交付 checklist(hldev 用)

> 吸收 ui-ux-pro-max 的 pre-delivery checklist。设计稿变成代码后,hldev 步骤 4(开发)对照本清单交付前自查。与上方设计稿自查(偏设计)互补,本清单偏代码实现。

- [ ] 无 emoji 当图标(用 SVG:Heroicons/Lucide)
- [ ] `cursor: pointer` 在所有可点击元素
- [ ] 只用触屏也能发现并执行关键操作，悬停提示可通过键盘聚焦访问
- [ ] 正文文字对比度 >= 4.5:1(亮模式)
- [ ] 从用户的起始页用 Tab 到达关键控件，用 Enter 或空格实际办理。焦点可见，关闭弹窗后回到触发处。
- [ ] 为关键按钮、表单控件和对话框按确认稿核对角色与可访问名称，使用浏览器契约的 `role` 与 `accessible_name` 断言。[界面对照契约](../hlbrowse/reference-check.md)
- [ ] 在系统开启减少动态效果时，移除非必要动画，保留加载进度和操作结果提示
- [ ] 表单提交失败后，错误与输入框关联，多处出错时可从错误摘要跳至对应字段
- [ ] 用真实长名称或连续编号及 200% 文字缩放检查换行，主操作仍能触达
- [ ] 按[产品场景](../hlpm/handoff-package.md#验收计划)约定的 CSS 视口验证受影响任务。菜单、弹窗等真实操作到预期结果，核对浮层是否阻挡下一步。
- [ ] 无障碍:ARIA 标签 + 键盘导航(详见 `hla11y`)
- [ ] 设计系统关键值(CSS 变量)与设计稿一致
- [ ] DEV-NOT-FOR-PROD 元信息已剥离(详见 §设计与实现分离)

## 设计原则

### 输出要求
- 设计稿必须输出为可预览的 HTML,用户可直接在浏览器中查看

### 设计稿 5 态覆盖(统一锚点)

> 按页面的操作与数据来源逐项核对这五种状态。设计稿呈现本期适用项，写明其余项的依据。原件未展示、由本项目补充的状态要注明项目决定。其他技能引用“5 态”时以此表为准。

- **hover 态** — 鼠标悬停效果
- **点击态** — 按下/激活状态
- **加载态** — 数据加载中的骨架屏/loading
- **空态** — 无数据时的提示与引导
- **错误态** — 错误提示与重试入口

### 设计评审自查清单
设计评审前,`designer` 需自查:
- [ ] 适用的控件状态和 PRD 规定的业务状态是否可触发并复核
- [ ] 是否遵循设计规范(有既有规范)或按 §设计系统推导产出自洽系统(无既有规范)
- [ ] 设计系统关键值(主色/字体/间距/圆角)是否在设计稿顶部注释列出
- [ ] 是否满足无障碍规范(WCAG 2.2 AA,详见 `hla11y` 技能)

## 无障碍要点(设计阶段)

> 完整无障碍规范见 `hla11y` 技能(跨设计→开发→测试三阶段)。本段仅列设计阶段最关键的 3 条:

- 色彩对比度 >= 4.5:1(正文文本),>= 3:1(大文本/UI 组件)
- 优先提供至少 24×24 CSS px 的点击区域。较小目标按[无障碍设计判例](../hla11y/SKILL.md#设计阶段)核对尺寸及适用例外。
- 不仅依赖颜色传达信息(配合图标/文字/形状)

## 设计与实现分离(🚨 DEV-NOT-FOR-PROD 白名单 · 单一可信源)

[hldev](../hldev/SKILL.md) 步骤 0 使用本段核对设计稿中的评审标记。

### 当前单页设计稿

每个页面交付一份可操作的 HTML。新[模板](../hlpm/templates/bl-marker/bl-marker-template.html)的普通链接用于演示，`?bl-review=1` 用于核对钉点、场景和验收表。进入实现时，保留页面结构、样式、业务状态和可访问性。移除仅供评审使用的 `.bl-pin`、`#bl-drawer`、`#bl-toggle`、`bl-marker.css`、`bl-marker.js` 以及测试面板。从同一组数据重走实际操作，按[已确认原型的复验方法](../hlpm/prototype-handoff.md)核对候选界面。
