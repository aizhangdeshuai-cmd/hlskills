# UI/UX 设计通用规范

> 属于 `hlskills` 技能系统。本文件是**通用 UI/UX 设计原则**的单一可信源;hlpm 流程实施细则见 `hlpm/design-spec.md`,开发段搬移规则见 `hldev` 步骤 0,两者均引用本文件的 DEV-NOT-FOR-PROD 白名单。

> ## ⚠️ 能力边界声明
> 本文件的"必须遵循""禁止搬生产"等是**文档纪律**,不是 Claude Code runtime 强制。靠加载本技能的 Agent 自觉 + 用户手动把关。DEV-NOT-FOR-PROD 白名单的"禁止搬生产"要真正阻断,需在 `hlhooks` 配 pre-commit hook 实测。

| 角色 | Agent |

| 设计师 | `designer` |
| 评审 | `designer` + `executor` |

## 设计依据优先级

### 1. 有设计规范文档
严格遵循项目已有的设计规范文档(设计系统、组件库、色彩/字体/间距规范),`designer` 不得偏离既定规范。

### 2. 无设计规范文档
`designer` 必须**先向用户询问**以下信息后方可开始设计:

- **设计风格偏好** — 极简、科技感、可爱、企业级、Material Design 等
- **色彩倾向** — 主色调、是否有品牌色
- **参考案例** — 用户是否有喜欢的同类产品界面(可读取截图/设计稿,用 Read 工具分析视觉特征)
- **响应式需求** — PC端 / 移动端 / 平板适配范围
- **参考图片** — 如用户提供参考设计图/截图,使用 Read 工具读取,提取色彩/字体/布局/间距

## 设计系统推导（无既有规范时）

> 当 6a.1 未找到既有设计规范时,`designer` 须按本节方法**推导出一套自洽的设计系统**,而非凭感觉拼凑。推导结果作为本次设计稿的规范依据,并建议沉淀到 `docs/design/spec.md` 供后续复用。
> 与 `designer` agent 协作:hldesign 定**推导方法**(下面 5 步),`designer` agent 出**具体设计值**并实现(框架检测/美学方向/领域适配,详见 `agents/designer.md`)。

### 0. 先避坑:LLM 设计默认偏见

`designer` agent 自带一个编辑向默认风格(暖米/奶油底 `#F4F1EA` + 衬线展示字 Georgia/Fraunces/Playfair + 斜体点缀 + 赤陶/琥珀强调色)。此默认**适合编辑/酒店/作品集/品牌**,**不适合**仪表盘/开发工具/金融/医疗/企业级/数据密集 UI。推导前先按需求领域判断:非编辑类须显式覆盖默认,给出具体替代色板(hex)+ 字体栈,不得用"不要米色""极简"等模糊否定(会滑向另一个固定默认)。

### 1. 色彩体系

从需求/品牌推导,产出 4 类 + 亮暗双套:

| 类别 | 推导方法 | 产出 |
|------|---------|------|
| 主色 | 品牌/行业基调(金融蓝/医疗绿/科技紫),1 个主 + hover/active/disabled 3 态 | `--primary` 及 3 态 |
| 辅色 | 主色的类比/互补色,1-2 个,用于次级操作 | `--secondary` |
| 语义色 | 固定映射:success(绿)/warning(黄)/error(红)/info(蓝),各含 normal/bg/border | `--success/warning/error/info` |
| 中性色 | 灰阶 5-7 级(bg/page/border/text/disabled),不用纯黑纯白 | `--gray-50` ~ `--gray-900` |

**自洽检查**:主色与语义色饱和度协调(不同色系不抢戏);中性色阶等距;亮/暗套对比度均达标(见无障碍要点)。

### 2. 字体系统

| 维度 | 推导方法 | 产出 |
|------|---------|------|
| 字体族 | 中文 1 个 + 英文 1 个 + 数字/等宽 1 个;按领域选(企业级用 Inter/思源;编辑类用衬线) | `--font-zh/en/mono` |
| 字号阶梯 | h1-h6 / body / caption / small,模块化比例(1.125 或 1.25) | `--text-xs` ~ `--text-3xl` |
| 字重 | light/regular/medium/bold,通常 2-3 档够用 | `--font-light/regular/medium/bold` |
| 行高 | 标题紧凑(1.2-1.3)/ 正文宽松(1.5-1.7) | `--leading-tight/normal/relaxed` |
| 字间距 | 标题负值收紧 / 正文 0 / 大写字母正值 | `--tracking-tight/normal/wide` |

### 3. 间距系统

- **基础单位**:通常 4px 或 8px(选一,全程一致)
- **阶梯**:xs(0.5x)/sm(1x)/md(2x)/lg(3x)/xl(5x),如 8px 基础 → 4/8/16/24/40
- **应用**:组件内 padding 用 sm-md,区块间距用 lg-xl,不乱用奇数值

### 4. 圆角与阴影

| 元素 | 圆角 | 阴影 |
|------|------|------|
| 按钮/输入框 | sm(2-4px) | hover 微影 |
| 卡片 | md(6-8px) | 1 层投影 |
| 弹窗/抽屉 | lg(12px) | 2-3 层投影 |
| 全屏遮罩 | 0 | 无 |

阴影用**层级**表达深度(z1 卡片 / z2 弹窗 / z3 全屏),不用颜色变化。

### 5. 核心组件规范

每个组件定**尺寸 + 状态 + 变体**:

- **按钮**:尺寸(large/default/small)× 变体(primary/secondary/ghost/danger)× 4 态(normal/hover/active/disabled/loading)
- **输入框**:尺寸 × 4 态(normal/focus/error/disabled)+ 必填标记
- **表格**:表头/行/边框/分页样式 + 奇偶行/hover/选中
- **弹窗**:宽度/圆角/阴影/header-body-footer 布局/遮罩

### 6. 布局方法论

1. **信息架构**:从 PRD 业务规则提炼页面信息层级(主/次/辅)
2. **栅格**:PC 12 列 / 移动 4 列,定义槽宽 + 间距
3. **视觉层级**:大小/对比/留白三件套引导视线(主操作大 + 主色,次操作小 + 辅色)
4. **对齐**:所有元素对齐到栅格或基础单位,不出现孤立的奇数间距

### 推导产出

推导完成后,在设计稿顶部 `<!-- 设计系统: ... -->` 注释里列出关键值(主色 hex/字体/间距单位/圆角),便于 6b.6 评审核对。建议同步沉淀到 `docs/design/spec.md`,后续项目复用。

### 行业→设计系统映射参考

> 吸收 ui-ux-pro-max 的行业推理规则理念。下表是主要行业的默认映射(非强制,用户/品牌明确要求优先)。推导时按需求所属行业查表,避免凭感觉。

| 行业 | 推荐风格 | 色彩情绪 | 字体情绪 | 反模式(禁) |
|------|---------|---------|---------|------------|
| 金融/银行 | Minimalism / Soft UI Evolution | 信任蓝/稳重深蓝/金 | Inter/思源(无衬线,稳) | AI 紫粉渐变、高饱和、卡通图标 |
| 医疗/健康 | Minimalism / Accessible & Ethical | 医疗绿/洁净白/柔和蓝 | Inter/思源(清晰易读) | 高饱和红、恐怖配图、过密信息 |
| SaaS/企业级 | Soft UI Evolution / Bento Grid | 品牌蓝/中性灰/语义色 | Inter/思源(专业) | 编辑向衬线、暖米底、手写体 |
| 电商/零售 | Flat Design / Bento Grid | 品牌色+促销红/信任蓝 | 无衬线(扫读快) | 过度动效、隐藏价格、复杂筛选 |
| 游戏/娱乐 | Dark Mode / Cyberpunk / 3D | 高饱和/霓虹/品牌色 | 个性展示字 | 企业级灰、银行蓝、极简留白 |
| 教育/儿童 | Claymorphism / Soft UI Evolution | 明亮活泼/柔和 | 圆润字体 | 冷峻黑灰、锐角、密集文字 |
| 政务/公益 | Accessible & Ethical / Minimalism | 国旗色/中性 | 思源/Inter(规范) | 花哨动效、暗黑模式、个性字体 |
| 编辑/作品集 | Editorial / Magazine(可接受 LLM 默认) | 暖米/衬线/赤陶 | Georgia/Fraunces | (本领域 LLM 默认反而合适) |

**使用方法**:识别需求所属行业 → 查表得推荐风格/色彩/字体 → 按本节步骤 1-6 推导具体值 → 检查反模式清单避免踩坑。行业不明或混合时,提 2-3 风格方向让用户选。

### 反模式库(各行业通用)

设计稿评审前,`designer` 须自查以下反模式(吸收 ui-ux-pro-max):

- ❌ **AI 紫粉渐变**用于非 AI 产品(银行/医疗/政务尤其禁)
- ❌ **emoji 当图标**(用 SVG:Heroicons/Lucide)
- ❌ **编辑向默认**(暖米/衬线/赤陶)用于仪表盘/开发工具/金融/医疗
- ❌ **高饱和红**用于医疗(除非错误态)
- ❌ **隐藏关键信息**(电商藏价格、金融藏费率)
- ❌ **过密信息**(医疗/政务数据密集但需留白)
- ❌ **无 hover/focus 态**(可点击元素缺反馈)
- ❌ **纯颜色传达信息**(色盲不友好,配合图标/文字)

## 代码级交付 checklist(hldev 用)

> 吸收 ui-ux-pro-max 的 pre-delivery checklist。设计稿变成代码后,hldev 步骤 4(开发)对照本清单交付前自查。与上方设计稿自查(偏设计)互补,本清单偏代码实现。

- [ ] 无 emoji 当图标(用 SVG:Heroicons/Lucide)
- [ ] `cursor: pointer` 在所有可点击元素
- [ ] hover 态有过渡(150-300ms)
- [ ] 正文文字对比度 >= 4.5:1(亮模式)
- [ ] 焦点态可见(键盘导航)
- [ ] `prefers-reduced-motion` 被尊重
- [ ] 响应式断点覆盖(375/768/1024/1440)
- [ ] 无障碍:ARIA 标签 + 键盘导航(详见 `hla11y`)
- [ ] 设计系统关键值(CSS 变量)与设计稿一致
- [ ] DEV-NOT-FOR-PROD 元信息已剥离(详见 §设计与实现分离)

## 设计原则

### 输出要求
- 设计稿必须输出为可预览的 HTML,用户可直接在浏览器中查看

### 设计稿 5 态覆盖(统一锚点)

> 交互逻辑需在设计稿中体现全部 5 态。其他技能(hldev/hltest/handoff-rejection)引用"5 态"时,以本定义为准。

- **hover 态** — 鼠标悬停效果
- **点击态** — 按下/激活状态
- **加载态** — 数据加载中的骨架屏/loading
- **空态** — 无数据时的提示与引导
- **错误态** — 错误提示与重试入口

### 设计评审自查清单
设计评审前,`designer` 需自查:
- [ ] 是否覆盖所有交互状态(5 态)
- [ ] 是否遵循设计规范(有既有规范)或按 §设计系统推导产出自洽系统(无既有规范)
- [ ] 设计系统关键值(主色/字体/间距/圆角)是否在设计稿顶部注释列出
- [ ] 是否满足无障碍规范(WCAG 2.2 AA,详见 `hla11y` 技能)

## 无障碍要点(设计阶段)

> 完整无障碍规范见 `hla11y` 技能(跨设计→开发→测试三阶段)。本段仅列设计阶段最关键的 3 条:

- 色彩对比度 >= 4.5:1(正文文本),>= 3:1(大文本/UI 组件)
- 交互目标最小尺寸 24x24px
- 不仅依赖颜色传达信息(配合图标/文字/形状)

## 设计与实现分离(🚨 DEV-NOT-FOR-PROD 白名单 · 单一可信源)

> 本段是 DEV-NOT-FOR-PROD 白名单的**唯一权威定义**。`hlpm/design-spec.md` §5 区块扩展、`hldev` 步骤 0 搬移规则,均引用本段,不重复定义。冲突时以本段为准。

设计稿 = **真实页面** + **元信息面板**,两者**严格分离**。dev 拿到设计稿**只搬真实页面**,**禁止搬元信息到生产代码**。

### 元信息列表(禁止搬生产代码)

设计稿可能含以下元信息,**全部不进生产代码**:

| 类别 | 例子 | 为什么不能搬 |
|------|------|------|
| diff 三件套 | 区块 1(原页面代码 / diff 基线)+ 区块 2(改动清单) | 仅评审用,生产代码无意义 |
| 弹窗状态演示 | 区块 3.2-3.5(4 个弹窗的打开状态截图) | 仅评审用,生产代码按需弹窗 |
| 逻辑说明层 | `🔗 角标` + 抽屉 + `<script id="logic-data">` JSON | 设计稿内嵌的 PRD/TC 引用,运行时不需要 |
| 悬浮元信息面板 | 右下角 `📋 元信息` 按钮 + 展开面板 | 仅评审用,运行时是 UI 噪音 |
| `data-prd` / `data-state` / `data-tc` / `data-matrix` / `data-diff-mode` 属性 | 任何挂载的逻辑指针属性 | 元信息载体,运行时无用且污染 DOM |
| diff 视觉辅助 | `.diff-add` / `.diff-mod` / `.diff-del` 选择器 | 评审视觉辅助,生产无需 |

### 生产代码搬运白名单

dev 拿到设计稿时,**只搬以下内容到生产代码**:

- ✅ **真实页面 DOM**:区块 3(含 3.1 默认 ACTIVE 状态)的所有元素
- ✅ **关联 CSS**:但**排除**以下类名/属性/选择器:
  - 类名:`.logic-*` / `.floating-meta-*` / `.logic-badge`
  - 属性:`[data-prd]` / `[data-state]` / `[data-tc]` / `[data-matrix]` / `[data-diff-mode]`
  - 选择器:`.diff-add` / `.diff-mod` / `.diff-del`
  - ID/脚本:`#logicPanel` / `#floatingMetaToggle` / `#floatingMetaPanel` / `#logic-data`
- ❌ 不搬区块 1-2-3.2-3.5-4-5 任何元信息
- ❌ 不搬右下角悬浮框
- ❌ 不搬 `<!-- DEV-NOT-FOR-PROD -->` 注释包裹的内容

### 5 区块扩展识别

如设计稿含 5 区块扩展(区块 3.2-3.5 弹窗在悬浮框 tab 内),**仅保留区块 3 + 3.1 DOM** 作为生产代码,其余 4 个区块禁止搬到生产。

### 自查清单

设计稿交付前,`designer` 需自查:
- [ ] 顶部有 `<!-- DEV-NOT-FOR-PROD -->` 注释 + 明确搬运白名单
- [ ] 区块 1-5 / 悬浮框外层有 `<!-- ⚠️ DEV-NOT-FOR-PROD -->` 围栏注释
- [ ] `data-*` 属性仅挂在真实页面元素上(元信息面板内部不算)
- [ ] 右下角悬浮框可正常展开/收起,不影响真实页面交互

dev 拿到设计稿时,需自查:
- [ ] 真实页面 DOM 完整可搬
- [ ] 元信息(区块 1-5 / 悬浮框 / `data-*` / `.logic-*` / `.diff-*` / `#floatingMeta*` / `#logic-data`)已剥离
- [ ] 运行时无 "📋 元信息" 按钮 / 🔗 角标 / logic-data 残留
