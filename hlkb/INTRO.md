# 为什么用项目知识库

项目知识库把接口约定、架构决定、常见错误和修复经验保存在项目根的 `knowledge/` 中。下一次会话直接从这些 Markdown 找回结论，旧提交也保留当时的版本。工作进度和待确认问题可以单独写进 `.hl/memory/working.md`。

例如，团队确认退款超时后应查询原交易。可以在该项目的错误码条目使用标题“退款结果待核对（REFUND_TIMEOUT）”，紧接着写明处理条件、生效版本和验证这一点的测试路径。后续接手的人搜索“退款”或错误码，便能从命中行读到依据。规则变化时在同一条目更新现行做法，并标注旧做法适用的版本。示例中的名称和规则应以本项目实际证据为准。

日常使用只需要一句问题和一个关键词。检索器在本机处理文件，返回少量原文摘录；需要更多上下文时再读取命中附近的行。查询命令、各类条目的归属与写法见[使用说明](README.md)。
