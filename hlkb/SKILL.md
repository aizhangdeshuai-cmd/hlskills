# hlkb · 项目知识库

## 找回知识

`PROJECT` 指目标项目根，`HLKB` 指本 SKILL.md 所在目录。从用户问句提取业务动作、别名或代码标识符检索，例如“改撤回申请要测什么”先查“撤回申请”。默认最多返回 3 条短摘录。证据不足时，用命中的路径和行号读原文。

```bash
python3 "$HLKB/kb.py" --root "$PROJECT" search '退款 REFUND_TIMEOUT'
python3 "$HLKB/kb.py" --root "$PROJECT" read knowledge/api/refunds.md 18 --lines 8
```

根据摘录中的状态、章节和原文位置核对适用版本及来源，回答附路径和行号。查旧规则时加版本词，如 `v1 退款 超时`。多词须命中同一文档。若“回冲 超时”无结果，可先查“回冲”，用词表命中的编号再查“REC_WAIT_V4 超时”。仍缺依据时核对代码、测试或决策原件。历史快照直接查看指定的 `knowledge/doc/v{N}/` 或旧包 `docs/v{N}/`。

查本次交接的验收编号或待决事项时用 `search 'AC-02' --handoff`，再用 `read <命中路径> <行号> --handoff` 读原文。在 `knowledge/prd.md` 正文独立一行保留唯一的 `[当前交接包](doc/v2/prd.md)`，版本换成本期实际值，旧目录用 `../docs/v2/prd.md`。代码围栏和 HTML 注释可保留历史示例。旧项目缺指针或需要查历史时可显式传 `--handoff docs/v2`。摘录属于产品稿，按原文区分已确认的决定与待决政策。

## 何时更新

需要长期记住的项目事实，先搜已有条目，在 `knowledge/` 原位更新。用稳定标题写清结论、适用范围、常用别名及可核对的来源。结论变更时注明新规则何时生效，给旧规则标明失效版本与替代位置。待办或未确认假设可放 `.hl/memory/working.md`。凭据只记变量名和获取途径。

收到 hllegacy 的[九类交付物](README.md#接收旧项目交付物)或[改动清单、分层规范及冲突](README.md#接收常见改动路径)时，先查已有正文，再原位更新，交接实际位置与核验状态。

写完另起一次检索，用实际会问的词找回原文并核对证据。交接给出路径、标题和适用版本。代码改变的业务或技术事实随实现同次提交。依赖提交 SHA 的验收记录可在同一 PR 后续补入，见[开发验证](../hldev/verification.md)。

## 同步触发表

初始化时建立 `knowledge/README.md`，仅为有内容的类别建档。维护或发布时按[13 类条目与交付自检](README.md#同步触发表)核对本期涉及项，补齐再交付。

## 项目约束文件

步骤 0 初始化或补全约束时，沿用本次选定的 Codex `AGENTS.md`、Claude Code `CLAUDE.md` 或 Cursor 项目规则。先去重宿主已有全局约束，再按[约束模板](templates/claude-md.template.md)补充项目指针和缺失的“🚨 完成前自检”段，保留原文与元数据。日常查询可直接运行检索命令。
