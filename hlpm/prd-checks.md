# 功能卡评审

| 强制规则 | 写法与完成判据 |
|---|---|
| STD-001 功能唯一编号 | 核对 4.3、功能卡和交接矩阵沿用同一 BL，迭代继承原 ID。通过附录的功能链接找到上游、下游及逐项优先级。优先级变更只在 4.3 调整等级，测试执行顺序和通过条件分别归验收标准分册 14.2、14.12。 |
| STD-002 字段完整性 | 每个受影响的页面字段有可定位的字段编号、业务定义及控件行为，共用字段引用原定义。逐项核对页面、弹窗、列表和接口可见结果。 |
| STD-003 逻辑完整性 | 从操作和对应规则推到界面反馈、状态和持久化结果，指明对象与下游。跨页、迁移和测试引用同一套术语；如旧状态需映射，逐项说明去向。 |
| STD-004 异常完整性 | 逐项核对适用的失败、边界和恢复路径，每项给出触发、反馈、数据后果、恢复操作和验收依据。 |
| STD-005 可验收性 | 对本期每个新增或变更，沿 BL → 字段/规则 → AC → 场景或 TC 找到一条能检出漏做或做反的验收。保留必要的旧行为回归及范围边界。遇到未决业务预期，回到[需求澄清](SKILL.md#需求澄清)。 |

交付前选一条跨章规则，沿业务概览、流程、功能卡、异常和验收读一遍。如果改一次扣减顺序，要在两处修改同一判断条件，就指定一处定义，另一处按规则号或小节引用。保留流程里的接手人、页面上的恢复入口，以及验收所需的输入和预期余额。对照同一 BL 的清单行和卡片开头，卡片只增加基线变化或来源；其他章节同义改写的重复也按此法复核。

## 正文与附件分工

读者只看 PRD 就应能判断谁在什么条件下做什么、操作后看到什么、怎样算通过。对照已选文件，把执行细节写到一个位置，正文用相对链接和条款、验收编号或用例编号定位。同一条验收条件只在所属功能卡定义。下表按内置标准目录列章号，客户目录按对应主题归位。固定目录保留各级编号，每个适用小节写本节的具体结论或验证重点，附对应明细。Mini 稿可在变更说明或验收段直接引用。

| 内容 | PRD 保留 | 分册或已有资料承载 |
|---|---|---|
| 第 07 章与验收标准 | 卡片定义 AC 的条件、业务动作和可观察结果。 | 测试阶段用 `acceptance-criteria.md` 写范围、通过条件和 BL/AC 验证索引，用 `test-cases.md` 写 TC、账号、数据、执行与恢复步骤。此前在卡内保留可验的业务场景。 |
| 数据与接口 | 卡内写清本次操作涉及的数据归属、单位、业务输入输出、失败或重复时的可观察结果。附录记录两项独立决定。 | 产品阶段按选择交 `data-requirements.md` 和/或 `interface-requirements.md`。核对选择、文件与附录链接相符；阶段内暂不出具的只记录安排。 |
| 第 11 章，非功能要求 | 写适用场景、影响放行的指标及依据。 | `non-functional-requirements.md` 展开负载、测量环境、方法及验证责任。没有已确认目标时先查依据，影响本期验收的回到澄清。 |
| 第 12、13 章，界面与异常 | 写关键交互、权限、失败后的数据与恢复去向。 | 选择原型时，页面、截图和操作实测归入 `design/`，正文链接具体页面或证据。详细的异常复现步骤归入所选用例。 |
| 竞品依据 | 写本期采纳的竞品行为及理由。 | 选做竞品报告时，样本、截图和比较过程进入 `analysis/competitive-analysis.md`。 |

例如已确认“同一笔审批回执送达两次只结算一次”，第 07 章 AC 写第二次回执后余额和流水应保持的结果，验收标准分册写“核对同一申请两次回执后的流水笔数”，并标对应用例。请求数据、两次发送步骤和查账方法写入该 TC。交付前从正文逐个打开所选附件，按编号或条款找到对应内容，核对双方预期。开发尚未编写的材料只记承接事项。任何“详见附件”或“见第 07 章对应 BL”都需补到读者能定位并判断结果。

## 复核关键数值

从生效规则或本次明确决定取输入、单位、计算口径及舍入方式，写清依据。用项目已有计算、精确算术或日期工具独立求值，再读成稿中同一对象、同一办理时点的实际文字。遇到时间、额度或归属条件时换一组有辨别力的输入，例如可用为零时批准已冻结的一笔。按业务需要核对分项、总数和有效记录数，单看合计可能漏掉记错账户的问题。

核对纯文本验收点时，`--expect-ac` 接受验收编号、带 `{}` 的原文短句和独立算出的值。短句须能定位该验收点中同一对象和时点的唯一读数，单位、精度与正文一致。例如入库前有 12 件，实际入库 3 件，正文应写“入库后库存为 15 件”。

```sh
python3 "$HLPM_DIR/handoff_trace.py" "$VERSION_DIR/prd.md" --stage prd \
  --expect-ac AC-1 '入库后库存为 {} 件' '15'
```

可重复传入不同的验收点或办理时点。沿用项目的自动化断言时直接比对成稿中的对应结果。文案或表内算例也从原规则复算，业务预期与原型实现有差异时先核实依据。交付说明写明核过的场景；目录检查、关键读数复算和候选实测分别报告实际结果。
