# 还原指定竞品的界面与操作

先把范围写成一条用户任务，例如“参考订单列表的筛选面板，覆盖打开、应用、取消和返回列表，沿用自家品牌”。沿用用户指定的产品、功能、目标设备及角色。只有提供了产品名时，先定位实际功能入口；宣传页只支持其中展示的画面。

## 观察原件

| 材料 | 能取得的证据 | 如何标出缺口 |
|---|---|---|
| 可操作网页或演示环境 | 在可访问角色下走真实路径，记录视口、数据前提、操作前后的页面和关键组件。需要焦点或关闭方式时，实际用键盘、遮罩等对应入口尝试。 | 登录后页面、缺少的数据或无法触发的异常标为待证，记录所缺角色、样本或操作。 |
| 屏幕录制 | 保留原件，按时间点标出触发动作、变化过程、稳定结果。动效有足够画面时补方向、起止关键帧与时长范围。[录屏取证](../hlmedia/SKILL.md) | 剪辑、倍速或看不见输入动作时注明限制。视频未展示的取消、键盘、失败等分支各自待证。 |
| 截图或设计图 | 定位可见状态与区域，对照布局、层级、颜色、控件与文案；记录已知视口或原图像素尺寸。 | 图片像素尺寸与网页 CSS 视口分别记录。单张图看不出的状态变化、断点或动效标为待证。 |

每个关键状态保留一处能回看的证据，例如“样本订单 18，桌面 1280×720，点击筛选后的面板区域”或“录屏 00:12–00:15”。网页记录产品、入口、采集日期及可见版本。移动端的手势、系统返回和触感依实际设备证据判断。原件与证据使用脱敏数据。后续按 TC 引用图、短片或测量记录，材料发生变化才重采受影响部分。

## 确定本项目的行为

分析时用等价业务数据走完对应的状态转换，包括本次要求覆盖的退出、失败或返回分支。需求澄清后，将原件位置、观察结果、本项目决定及关联 AC/TC 写入 PRD 控件行为表。逐项确定采用、调整或待证的依据。

- **采用。** 把已观察到且本项目需要跟随的细节写成具体预期，例如“菜单左沿与触发按钮左沿对齐，Esc 关闭后焦点回到该按钮”。上例涉及外观、关闭动作、焦点三个观察，分别取证；可独立漏验的要求分配独立 TC。
- **调整。** 例如“品牌色沿用项目组件，仅跟随定位和关闭行为”。记录决定和适用维度。颜色按项目规范验证，位置和关闭继续与原件比较。项目的无障碍改进也写明依据及验收条件。
- **待证。** 只拍到展开状态时，Esc、焦点去向均待证。若用户另外决定本项目支持 Esc，把该决定记为本项目要求。竞品是否支持仍标为未知。必测参考项缺证据时先补材料；仍影响本期预期的，按[需求澄清](SKILL.md#需求澄清)由用户确认行为或明确移出本期。

## 对照与交接

为要求跟随竞品的场景填写 `reference`，绑定原始证据和要对照的维度。可操作网页先采集参考基线，再用该 TC 契约的视口、等价数据和相同操作对照原型及开发候选。浏览器契约覆盖这一任务对应的终态，例如订单导出须实际点中菜单项并看到本次导出的完成反馈。两边控件的选择器可以不同。几何容差按本条布局的判定依据设置。查看截图时关注约定的区域，原型评审钉点可隐藏。记录指向具体差异，例如“面板应与按钮左沿对齐，实测向右偏 260 CSS px”。[浏览器采集和对照命令](../hlbrowse/reference-check.md) · [产品包字段与交接检查](handoff-package.md#竞品交互证据)

截图、录屏和设备实测使用人工对照记录，写明原件位置、候选实际观察、参与者、结果及证据。只对已观察且已验证的维度给出通过结论。原型对照入设计交接，开发候选使用其真实版本的 QA 记录复验。对比结果逐 TC 列出一致项、约定调整、实际差异与待证项。
