# 原型逐条核对 PRD

从本期每个 BL 的 AC 取预期，再读它引用的业务规则、交互和异常条款。同一 AC 有多个会改变办理结果的分支时分开操作。例如“结果未知可恢复”至少要区分请求是否已经写入。只选与该需求相符的检查；纯查询页面可核对筛选结果、笔数及原记录，涉及扣减或审批时再展开相应分支。记录方式见[原型设计与验证](design-stage.md)。

## 交互与数据

- **表单、筛选或弹窗。** 从约定角色和入口实际点击。核对默认值、处理中可用的按钮、成功反馈、筛选后的行与笔数、弹窗关闭后的焦点。填写后取消或按约定快捷键退出，再重开、刷新，检查草稿和已保存记录各自的去留。有移动端承诺时，用对应视口完成同一操作。
- **输入有边界或优先级。** 分别提交刚好合法和刚好超限的值；同时制造两个错误，核对第一个提示、焦点、保留的输入。修正后再提交，查记录是否仅新增一次。长度、空白、日期区间均取 PRD 的计量口径。
- **操作会改变业务数据。** 先记对象标识、状态、数值与记录数，按 PRD 独立算出操作后应有的值，再对照列表、详情及业务流水。拒绝、取消、刷新时也核账。若存在额度或库存预留，分清占用、结算、释放各自影响的字段，选一个“可用为零但已预留”的样例复验。例如可用／预留／已用为 0／5／3，确认消费预留的 5 后应为 0／0／8。
- **多个角色或页面看同一对象。** 让一方在另一方保持详情或确认框打开时办理。从两端按同一编号，在约定的自动更新或刷新时点核对当前状态、摘要、明细、反馈和可用动作。分别看主动端和被动端的筛选与焦点。切换到另一对象，核对其原数据以及上一对象的回执有无残留。

例如预约改期只涉及一个详情页。从 13:30 改选已满的 14:00，检查弹窗仍选 14:00、原预约仍为 13:30、改期次数仍为 0；改选 15:00 成功后，刷新应见 15:00 和 1 次改期。

## 异常与恢复

- **读取失败。** 先把样例办成一个区别于初始值的状态，再中断读取。核对未知值、失败提示和允许的动作；恢复条件实际生效后从业务页重读，核对原编号、笔数及数值。演示开关异步生效时，给操作者一个能判断何时重读的反馈。
- **写入结果未知。** 分别在写入前中断、写入成功后丢回执；刷新后用原请求标识查询。仍未知时保留待核，明确查无且业务条件仍有效时才开放同标识重试。命中时给出原单及其当前状态，收起重发；让另一人继续处理，再看查回的状态是否随原单更新。查无但原单已终结时核对相应反馈。若要求幂等，用相同标识重放后数有效业务事件，重试次数和有效写入次数分别记录。
- **权限或关联可在办理中改变。** 打开确认框后撤销权限或停用对象，再从原窗口确认；也试一次变更通知尚未到达的情况。核对写入被拒、原对象无变化，以及对象选择器、摘要、列表、详情、回执均按当前权限展示。用仍有权的身份或对象走通正常路径，恢复授权后再查一次。
- **并发或互斥决定。** 两端先读同一个起点。对同一对象作相反决定时交换成功顺序；对不同对象争用同一资源时选择“单笔足额、合计超额”的输入。比较两端刷新后的原单、数值、失败方反馈及有效事件数，核实 PRD 允许几个操作生效。

在已有验证记录中把观察到的文字、数值或控件状态回指 AC。若改错一次扣减或让回执显示旧状态仍能通过，补上能区分正确与错误结果的断言，再复跑受影响分支。本地多标签模拟仅覆盖所演示的行为；真实身份、跨设备事务和服务端审计等候选环境项写明复验条件。政策待定时记录本次演示假设、负责人和确认节点。
