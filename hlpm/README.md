# hlpm 使用说明

在需求前写「用 hlpm」并说明这次想拿到什么。支持斜杠命令的宿主也可以使用 `/hlpm`。

| 本次需要 | 可以直接这样说 | 交付到哪里 |
|---|---|---|
| 写 PRD | 用 hlpm 给现有假期池写一份半天假 PRD，说明扣减、撤销和旧单如何处理。 | 拿到本版 `prd.md`，可核对业务规则、字段、异常和验收条件。 |
| 做可演示原型 | 基于这份 PRD，用 hlpm 做一个可以申请和撤销半天假的原型给我看。 | 拿到可操作的 HTML 和逐条验收记录。每个 AC 都能查到实际反馈、数据变化、异常恢复或不适用原因，以及候选环境待验项。[原型检查项](prototype-checks.md) |
| 完整交接 | 半天假方案确认了，用 hlpm 把本版整理好，正式交给开发和测试。 | 拿到版本目录、PRD、验收用例、非功能要求、一致性矩阵和自检结果，以及本期适用的原型和证据。 |

这三句话也可以分几次提出。接续时提供上次的版本目录、PRD 或原型入口，技能按本期变更补齐需要的内容。[完整流程](SKILL.md)

## PRD 输出长啥样

已有产品默认用迭代 PRD（原 Mini PRD），写清旧行为、新行为及要回归的范围。从零建设默认用标准 PRD，先讲目标、业务流程和模块关系。两种形式都可直接指定。适用的数据需求设计、接口需求设计分别选择由产品或开发编写，PRD 始终写清业务结果和验收依据。[迭代 PRD](prd-mini.md) · [标准 PRD](prd-cards.md)

企业标准版有 17 章。第 7 章的一张功能卡把字段、真实操作、数据变化、异常恢复和可执行的验收场景放在一起。可直接查看“新建项目分类”如何处理两人同时保存同名分类，以及怎样确认只创建了一条记录。[五档需求规模](SKILL.md#按需求规模裁剪) · [可复制的企业模板](templates/enterprise-prd.md) · [单功能完整示例](prd-feature.md)

生成后按选定目录运行检查。企业全目录使用 `python3 hlpm/handoff_trace.py <PRD路径> --enterprise`。新功能模块使用 `--module`，默认保留 01～14、16、17，涉及发布时补第 15 章。客户固定 16 章时使用 `--outline <已确认目录路径>`。检查核对逐级编号、正文、功能卡及验收索引。不适用项写明原因，待确认项写负责人和确认节点。迭代稿检查功能点与验收条件。业务与原型仍用实际场景验证。

## 版本目录

新版本保存在业务项目的 `knowledge/doc/vN/`。续写已有版本时沿用其实际目录，包括旧项目的 `docs/vN/`。看结果时从本次返回的路径进入。[版本目录约定](path-conventions.md)

## 评审模式

可为本次交付的 PRD、设计或用例选择评审或免审。正式交接时，开发根据相同的版本、验收条件和证据复核；若某项退回，按拒收单指出的条款补齐。[交接清单](handoff-package.md) · [开发接收规则](../hldev/SKILL.md)
