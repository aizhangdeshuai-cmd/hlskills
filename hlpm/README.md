# 使用 hlpm

说「用 hlpm 做一个假期池」即可启动默认全流程。先聊清要解决的问题、范围、业务规则和异常，再核对工作空间里的现有项目、询问竞品参考及交付清单。已确认的规则直接沿用。你可以指定只做分析、PRD、原型，或选定几样交付物。

| 阶段 | 你会拿到什么 |
|---|---|
| PRD | 按规模交一页变更、Mini 或标准 PRD。功能卡写明业务动作、数据结果和异常。数据需求和接口需求分别确认是否在产品阶段成文，其他选定的产品文档一起交。 |
| 高保真原型 | 从 PRD 打开能实际办理业务的页面，按同一条验收条件复演，查看交互反馈、数据变化、失败后如何恢复及实测记录。纯服务需求可约定跳过。 |
| 测试 | 分册版交 `acceptance-criteria.md` 和 `test-cases.md`。可按功能和验收编号找到用例的前提、操作、预期和验证方式。 |

每做完一阶段都会询问是否评审。可选本阶段的全部角色、部分角色或跳过。发现问题后，同一版本里受影响的 PRD、原型、用例和证据一起更新，再由你选择复审或继续。[流程与三次评审](SKILL.md#角色与评审记录)

例如，「给现有订单列表只写一份调整默认分页的 PRD」会停在 PRD。「把已确认的方案正式交给开发和测试」会继续补齐计划、矩阵和交接检查。新版本通常在业务项目的 `knowledge/doc/vN/`，续写按已有版本的实际路径。[迭代写法](prd-mini.md) · [标准写法](prd-cards.md) · [正式交接](handoff-package.md)
