# 步骤 4b · 迭代 PRD（Mini PRD）

已有项目默认使用迭代 PRD，原称 Mini PRD。首页让接手者看懂原来怎样、本次改什么、影响谁、怎样验。局部变更可以写在一页；涉及多个模块时展开受影响的流程、数据归属与回归场景。用户可改选[标准 PRD](prd-cards.md)。

常规写法可将七项合并到同一份 `prd.md`，用户指定七个小节时，依次使用「需求基本信息、需求背景及目标、需求范围、详细需求说明、业务规则及异常处理、验收标准、影响范围及风险」。需要单列验收章节时，在所属 BL 下保留验收定义，该章节按 AC 指回定义处。

按[需求规模](SKILL.md#按需求规模裁剪)决定写到什么深度。微小迭代用一个变更前后的具体例子覆盖背景、范围、功能及验收。普通迭代再写清受影响的角色、依赖、回归和待决事项。字段或规则有变化时沿用已有编号，在同一 BL 内写明新旧值、判断条件及关联 AC。共用字段和未变规则引用生效版本。

## 一页变更说明

| 内容 | 在正文中怎样呈现 |
|---|---|
| 1 基本信息 | 标题写需求名称，首行列工单或需求编号、模块、优先级、计划版本和来源。提出人、计划日期等已有信息直接引用工单，缺少且影响交付时注明待确认。 |
| 2 背景与目标、3 范围 | 开头用两三句话写明当前问题、受影响的用户、这次怎样算改好。引用生效文档或可复核的现有实现，列出涉及的页面或功能。已有项目新增能力时标明本期新增，旧行为缺少依据时列入未确认需求。 |
| 4 详细变更、5 规则与异常 | 在所属 `## BL-1 功能名称` 下并排说明「原行为 → 新行为」，列出改变的操作、字段、默认值、权限或数据规则。只有会改变结果的分支才展开，说明失败后用户能看到什么、如何继续。 |
| 6 验收 | 在所属 BL 下定义 AC，以可观察的输入、结果、数据副作用核对正常、异常、边界和受影响的回归路径。仅交 PRD 时，验收场景可直接写在卡内，已有 TC 可引用。完整交接时，将可独立漏验的场景分别关联到实际 TC。 |
| 7 影响范围及风险 | 说明受影响的入口、下游、旧数据兼容性与迁移依据。待确认事项及风险仅设「未确认需求」「外部依赖」「后续优化事项」三栏。有实项写负责人、处理节点和关联 BL 或 AC，已确认的规则与异常回填到对应 BL。 |

数据需求设计、接口需求设计均可选，按用户对两项分别确认的分工处理。产品侧写时，把变更的数据定义或交换约定写在所属 BL，已有字典、契约按版本引用。开发侧写时，在 BL 保留业务口径、上下游可观察的结果及 AC，记下承接方与待补的技术设计。无相关变更的项可省略。

保留基线中的 BL、AC、TC 编号，每个 AC 只在所属 BL 定义一次。下面是一份虚构的局部参数变更示例。实际文档使用真实 Markdown 标题和表格。

```markdown
# 订单查询默认每页 50 条

需求 ORD-18 由客服组提出，归属订单查询模块，优先级 P2。沿用 v2.3 订单查询规范 BL-2，采用迭代 PRD，计划版本 v2.4，状态为待评审。数据需求设计本次不涉及，接口需求设计由订单服务开发承接。

## BL-2 订单列表的默认条数

客服核对月末订单时，每页 20 条需要频繁翻页。本期把省略 limit 时的默认上限从 20 改为 50。范围为订单查询接口，同一接口已有的显式分页参数仍优先。

| AC | 验收点 | 可追溯测试 |
|---|---|---|
| AC-12 | 有 60 条可见订单时，省略 limit 取回前 50 条；只有 7 条时返回这 7 条。 | TC-21、TC-22 |
| AC-13 | 同一批 60 条订单，旧客户端显式传入 limit=20，仍按原排序取回前 20 条。 | TC-23 |

历史订单和保存的条件无需迁移。按 AC-12、AC-13 更新查询契约。省略 limit 的调用方单页最多多取 30 条，发布前按 v2.3 既有响应时间目标复核。

| 未确认需求 | 外部依赖 | 后续优化事项 |
|---|---|---|
| 无 | 无 | 无 |
```

## 界面差异与原型

在受影响的 BL 下写清角色、入口或控件、操作和可见反馈。仅交 PRD 时，用具体场景和预期解释变化。交付原型时，加上已生成的同版 `design/` 页面；字段、错误、焦点或恢复有变化时，在实测后关联 AC、步骤和已有截图。十个页面共用一句提示时，列全入口，文案与规则定义一次。需要开发 1:1 还原时，交接已确认的原型版本、视口、状态和允许差异。[原型还原交接](prototype-handoff.md)

已有规则按版本和条款引用，适用的原型、验收计划、实测证据及交接沿用同一条 BL → AC → TC 链。原型入口指向本版实际页面，证据指向该 TC 的实测记录。[交付包与检查器](handoff-package.md)
